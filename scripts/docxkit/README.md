# docxkit — сборка и проверка документов для людей

Появился после 10.09.2026: документ ушёл заказчику с разъехавшейся таблицей,
потому что я ни разу на него не посмотрел. LibreOffice на этой машине не работает
(не открывает даже .txt), поэтому визуальной проверки не было вообще.

## Как пользоваться

```bash
# собрать документ, используя builder
# затем ОБЯЗАТЕЛЬНО:
python3 ~/scripts/docxkit/check.py Документ.docx ~/render/check 8
```

`check.py` печатает проблемы вёрстки и раскладывает страницы в PNG.
**Картинки надо открыть и посмотреть.** Автопроверка ловит геометрию,
глаз ловит остальное.

## Что внутри

| файл | зачем |
|---|---|
| `builder.py` | стили и утилиты сборки: `table_layout` (фиксированные колонки), `nbsp`, `repeat_header`, `keep_rows_together`, `page_break_before` |
| `preflight.py` | автопроверка: autofit, переполнение колонок, разорванные числа, порядок XML, пустые абзацы с разрывом |
| `docx_to_html.py` | .docx → HTML с той же геометрией страницы |
| `preview.py` | HTML → PDF → PNG постранично, через браузер из `~/browser-tools` |
| `check.py` | всё вместе |

## Грабли, на которые уже наступили

- **Ручная вставка узлов в OOXML ломает файл.** Порядок элементов в `tblPr`,
  `tcPr`, `trPr` строго задан схемой. `append` кладёт в конец — Word ещё простит,
  LibreOffice уже нет. Использовать API python-docx (`table.autofit`, `cell.width`)
  или `insert_element_before` с перечислением последующих тегов.
- **Без `tblLayout=fixed` заданные ширины колонок игнорируются** — Word пересчитает
  их по содержимому, и колонка с длинным текстом сожмётся до нечитаемой.
- **Числа с обычным пробелом рвутся между строками:** «350 000 ₽» превращается
  в «350» и «000 ₽». Прогонять весь текст через `nbsp()`.
- **Пустой абзац с разрывом страницы** показывается в мобильных просмотрщиках
  пустым квадратом. Разрыв задавать свойством `page_break_before` у заголовка.
- **Системный playwright не запускается**, нужен из `~/browser-tools/venv`
  с их `LD_LIBRARY_PATH`.
- **В системе только DejaVu Sans**, он шире Calibri примерно на десятую часть.
  Превью поэтому пессимистично: что влезло в превью — влезет и в Word.
