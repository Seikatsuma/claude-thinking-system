# topics — память дела между чатами

Страница состояния дела, которую копит чат по ходу и поднимает любой новый чат по запросу
(«продолжаем про …»). Заменила Stop-хук `session-handoff.sh` (писал первую фразу и последнюю
строку — для продолжения бесполезно; его старые файлы в `~/vault/sessions/` не тронуты).
Решение принято с пользователем 10–13.09.26 после двух кругов критики; сравнивали с Memory Bank
(Cline) и записью решений ADR.

## Где что
- `topic.py` — всё: new/open/now/mode/decide/squeeze/spill/tail/list/find/skip/oneoff/
  memory-pending/memory-done/lifecycle. `--help` у каждой команды.
- `~/.claude/hooks/topic-prompt.py` (UserPromptSubmit) — счётчик сообщений чата; подсказка
  «подними тему», только если чат без темы и пользователь продолжает прошлое дело. Служебные сообщения
  (уведомления фоновых задач, отзывы Stop-хуков, пересказ после сжатия, письма соседних чатов) не
  считает — список маркеров общий с `task-framing.sh`, менять в обоих (14.09.26).
- `~/.claude/hooks/topic-gate.py` (Stop) — **снят из settings.json 15.09.26 по просьбе пользователя** (возвращал агента ≈110 раз в день, мешал доводить задачу); файл оставлен, вернуть = строка в Stop
  на страницу; один раз — если чат без темы после 4 сообщений.
- Данные: `~/vault/topics/<слаг>/` (уезжает в приватный GitHub вместе с vault),
  архив `~/vault/topics/_archive/`, очередь в долгую память `_to-memory.jsonl`.
  Состояние чатов и замки: `~/.claude/hooks/state/topics/`.
- Крон 05:40 `topic.py lifecycle`, журнал `~/.claude/hooks/state/topics/lifecycle.log`.

## Страница темы (граница с другими памятями)
- `mode.md` — режим работы (роль чата, что нельзя, как говорить с пользователем). Грузится первым:
  режим виден только по поведению, в конспект «что сделано» он не попадает — дыра №1 с пользователем.
- `now.md` — где мы и следующий шаг. Раздел на каждый чат (`<!-- chat:метка -->`), чат
  перезаписывает только свой — параллельные чаты не затирают друг друга. Потолок 4000
  знаков на всю страницу; при переполнении отказ, а не обрезка. Чужие разделы, уже сведённые
  в свой, — `--absorb`, их текст уходит в `spill.md`. Раздел чата, говорившего меньше 2 ч назад,
  вбирать нельзя (код 6): 13.09 живой тест вобрал раздел работающего соседа. Уборка руками — `TOPICS_FORCE_ABSORB=1`.
- `decisions.md` — только дописывается: дата · что — почему, отклонённое строкой (иначе новый
  чат ходит по кругу).
  **Что обязано попасть в decisions (15.09.26):** требования пользователя к устройству
  результата — порядок блоков, что выше/ниже, какие уровни, что в меню, что отдельным блоком — особенно
  сказанные голосом или в расшифровке. Записывать `decide` в том же ответе, где требование прозвучало,
  а не в конце дела и не в `now`: 15.09 устройство интерфейса из 10-минутной расшифровки жило только в
  переписке и `now`, чат дважды за день сделал не так («копия интерфейса», «пять блоков должны быть выше»). Больше 6000 — `squeeze` сводкой, полное — в `decisions-archive.md`.
- Тема ≠ долгая память. Тема — «где мы в этом деле»; вывод, верный вне темы, помечается
  `decide --global` и переносится в `memory/` (очередь `memory-pending`).

## Неочевидное
- Писать может только чат, у которого есть состояние от хука на сообщение. Помощники
  (`claude -p` из воркфлоу/критиков) хуков не получают — проверено 13.09: 18 из 21 чата
  после установки хуков были помощниками. Их черновой ресёрч в тему не попадает.
- Секреты: запись с ключом отклоняется (код 5). Указатель `~/.secrets/x.env` можно.
- Поиск темы нечёткий (транслит + похожие слова): пользователь диктует голосом. При двух близких
  кандидатах `open` отказывает (код 4) — один закрытый вопрос пользователю, не угадывать.
- `open` предупреждает «ОТСТАЁТ», если пользователь писал привязанному чату после его последней записи
  (обрыв, лимит) — по счётчику хука; у чатов без счётчика — если говорил >30 мин после записи.
  Порог по времени 120 с давал ложное «ОТСТАЁТ» почти на каждом последнем ответе (проверяющий 13.09). Хвост: `tail <метка>` — читать помощником, в основной чат нести выжимку.
- Архив — 21 день без обращений И ни один привязанный чат не писал 21 день (сезонные темы
  вроде закрытия месяца поднимаются по упоминанию, `open` ищет и в архиве).
- Удаление из архива — 90 дней, только если нет непереносённых `--global` выводов.
  Разрешение пользователя 13.09.26 покрывает ТОЛЬКО это. Переписки чатов (`projects/*.jsonl`)
  не удаляются: веб-интерфейс строит из них список «мои чаты».
- Хуки прописаны в `~/.claude/settings.json`; `~/.claude-webuser-1` (веб-чаты пользователя) — ссылка на
  `~/.claude`, то есть тот же файл. Второй аккаунт (`~/.claude-account2`) своих хуков не имеет, но
  чат в каталоге `~` берёт их из проектных настроек того же файла — проверено 13.09 чатом под
  вторым аккаунтом (отметка хука появилась, несмотря на «workspace not trusted»). В каталогах
  других проектов у второго аккаунта хуков нет — по устройству настроек, не проверялось.
- `verify-resume.sh` (чужая подсистема проверки результата) велит новому чату «забрать хвосты»
  и у ЖИВЫХ параллельных чатов того же каталога. Живой тест 13.09 так отвлёкся: поднял тему и
  ушёл разбирать чужие пункты. Тестировать подъём темы — из каталога без хвостов (`~/vault`).
- Проверка качества страницы: новый чат только по ней отвечает «где мы / почему так / что
  дальше». Два «ты забыл, что мы решили» в теме — `topic-prompt.py` поднимает флаг: чинить
  формат, а не одну страницу.

- 14.09.26: topic-gate пороги LAG_PROMPTS=8, LAG_UNBOUND=8 (было 3/4) — запись одна в конце задачи, каждый возврат гейтом стоил шаг по всей переписке.
