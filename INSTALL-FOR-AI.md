# Установка системы мышления (инструкция для ИИ-агента)

Ты — Claude Code на машине пользователя. Поставь полный набор так, чтобы у пользователя **ничего не потерялось**, а всё, что уже помогает ему работать, осталось и стало частью единой системы.

## 0. Как работать во время установки
- Установка длинная. Веди файл состояния `~/thinking-install/STATUS.md`: этапы ниже чек-листом, после каждого этапа — отметка и одна строка итога. Если сессия оборвалась, следующий ответ начинается с чтения этого файла и продолжения с первого незакрытого этапа — не с начала.
- Не заканчивай ответ, пока не пройдены все этапы и самопроверка. Не спрашивай пользователя о технических решениях — принимай сам, называя выбор строкой.
- Долгое (дольше ~5 минут) — через `systemd-run --user --unit=job-<имя> --collect bash -lc '… > ~/logs/job-<имя>.log 2>&1'`, ожидание короткими проверками в этом же ответе. Не `nohup`/`&`.
- Службу веб-интерфейса, в которой идёт этот чат, во время установки **не перезапускать**: хуки и правила подхватываются новыми сессиями сами.
- Ничего не удалять. Заменяемое — сначала в резервную копию.

## 1. Резервная копия
`~/thinking-install/backup-<дата-время>/`: `~/CLAUDE.md` (если есть), и для КАЖДОГО каталога настроек Claude (`~/.claude` и все `~/.claude-*`, где есть `settings.json` или `CLAUDE.md`) — `CLAUDE.md`, `settings.json`, `hooks/`, `agents/`, `skills/`, `workspace/`, `projects/*/memory/`. Плюс `~/scripts/` если есть. Проверь, что копия не пустая (`du -sh`).

## 2. Опись того, что уже есть («мозги» сервера)
Составь `~/thinking-install/INVENTORY.md`:
- все `CLAUDE.md` в домашней папке (до глубины 3) и в каталогах настроек; блоки между метками `<!-- claude-ui:start -->` / `<!-- claude-ui:end -->` — это блок программы веб-интерфейса, он обновляется ею самой;
- хуки из всех `settings.json`, помощники (`agents/`), навыки (`skills/`), рабочие файлы (`workspace/`), память (`projects/*/memory/`), свои скрипты;
- другие ИИ-контуры на машине (боты, другие пользователи с `.claude`, их промпты и правила) — если доступ есть (`sudo -n true`), прочитай их правила и промпты; ничего в них не меняй;
- прошлые резервные копии прошлых установок (`~/claude-backup-*`) — что в них было и что потом убрали, и по чьей просьбе (смотри переписку чатов в `projects/*/*.jsonl`, если нужно понять причину).
Для каждого найденного правила — пометка: **оставить как есть / влить в систему / уже покрыто системой / противоречит (чем)**. Правила пользователя важнее правил набора; решение по противоречию — в пользу явной просьбы пользователя, с записью в INVENTORY.

## 3. Файлы набора
Склонируй репозиторий во временный каталог и скопируй с сохранением путей:
- `.claude/hooks/`, `.claude/agents/`, `.claude/skills/`, `.claude/workspace/`, `.claude/docs/`, `.claude/learning-loop/` → в `~/.claude/`;
- `scripts/` → `~/scripts/`.
Файл с тем же именем уже есть и отличается — не затирай молча: оставь версию пользователя, если она его (сравни с резервной копией и историей), или объедини; итог — в INVENTORY.
Навыки `docx` и `xlsx` (документы Word и таблицы Excel) в набор не входят по лицензии — поставь их из официального https://github.com/anthropics/skills (каталоги `skills/docx`, `skills/xlsx` → `~/.claude/skills/`), если их ещё нет.
Просмотр страниц документов (`~/scripts/docxkit/check.py`) рисует их браузером: `pip install --user playwright && python3 -m playwright install --with-deps chromium` (или готовый Python с playwright в переменной `DOCXKIT_PYTHON`); проверка — `python3 -c "import playwright"`.
`chmod +x ~/.claude/hooks/*.sh ~/scripts/*.sh`. Инициализация петли обучения: `python3 ~/.claude/learning-loop/loop.py init`. Папки: `mkdir -p ~/logs ~/vault/topics`.

## 4. Правила (CLAUDE.md)
Для КАЖДОГО каталога настроек, которым реально пользуются чаты (`~/.claude` и каждый `~/.claude-webuser-*`; если это символическая ссылка — один раз):
- блок `claude-ui` между метками не трогать;
- после него (или в конец) — текст `CLAUDE.md` набора целиком, между метками `<!-- thinking-system:start -->` и `<!-- thinking-system:end -->` (при повторной установке заменять только содержимое между этими метками);
- правила пользователя, найденные в описи и помеченные «оставить» / «влить», — отдельным разделом «Правила этого сервера» после блока системы, дословно;
- пути в тексте (`~/.claude/workspace/…`, `~/.claude/docs/…`) ведут в `~/.claude` — проверь, что файлы там есть.

## 5. Хуки (settings.json)
Для КАЖДОГО каталога настроек из п. 4: не заменяй файл целиком. Для каждого события из `hooks` в `.claude/settings.json` набора допиши элементы в конец массива этого события, если такой команды ещё нет (сравнение по имени файла хука); события нет — создай. Чужие хуки пользователя не удаляй. Остальные поля (`theme`, разрешения и т. п.) не трогай. Проверь, что JSON валиден.

## 6. Среда для долгих задач
- `loginctl enable-linger "$USER"` (через `sudo`, если нужно) — без этого задачи `systemd-run --user` гаснут при выходе; проверь `loginctl show-user "$USER" -p Linger` → `yes`.
- Проверь, что `systemd-run --user --unit=job-selftest --collect true` отрабатывает (`systemctl --user status job-selftest` или код возврата 0).
- Оповещения (необязательно): если у пользователя есть свой Telegram-бот и его личный chat id известен однозначно — `~/.secrets/notify.env` (chmod 600) с `NOTIFY_TG_TOKEN`, `NOTIFY_TG_CHAT`; проверка `~/scripts/notify.sh "проверка связи"`. Неоднозначно — пропустить и сказать об этом пользователю одной строкой.
- Сторож сервера (если оповещения настроены): строка в crontab пользователя `*/5 * * * * ~/scripts/watchdog.sh >/dev/null 2>&1`, если её ещё нет.

## 7. USER.md и WORDS.md
`~/.claude/workspace/USER.md` заполни по тому, что уже известно из правил и переписки на сервере (кто пользователь, как объяснять, что можно без вопросов, язык) — не расспрашивай, если это есть в файлах. Слова пользователя, на которых модель уже ошибалась в переписке (голосовые искажения, двусмысленные слова), — допиши в `WORDS.md` в его формате.

## 8. Самопроверка делом
`bash ~/scripts/thinking-selftest.sh` → должно быть `ИТОГ: N из N`. Сбой — исправить и прогнать снова. Дополнительно: `python3 -c "import json;json.load(open('<каждый settings.json>'))"`.

## 9. Отчёт пользователю
Коротко, простыми словами, без команд: что стало (система мышления, помощники, навыки, защиты, долгие задачи не обрываются), что из прежнего сохранено и влито (по описи), где резервная копия, что не сделано и почему (например, оповещения). Итог самопроверки — цифрой. Новые правила действуют в новых чатах.
